- **主任務會顯示子任務的 agent 是不是真的在做，以及子任務之間怎麼交棒（#4335）。** 「進行中」只是狀態，不代表 agent 正在做，所以主任務頁的每個子任務底下多了一行：執行中時是轉動的指示加上它現在在做什麼（「dev · 編輯 src/game.js」）——沒有提供步驟時（不是管理員、該 agent 的 `tool_progress` 關閉、或「顯示活動」關閉）只顯示狀態；其他子任務則顯示「等 S-1」，接著是「已交給 dev」→「dev 已讀」，交接沒送到時會說明原因（agent 離線或暫停、任務板關閉、通知遺失）；卡住的子任務會寫出原因，agent 在等你回應或似乎卡住時會明講，閒置的 agent 就標示閒置。主任務的「Agent 活動」不再只寫「工作在子任務裡」，而是列出同樣的內容；有子任務的 agent 在執行時，狀態旁會多一個「執行中」；動態裡多了子任務的狀態變更，以及每次交接一列（「S-1 完成 → 已交給 dev 開始 S-2」，底下是目前進度）。下一個子任務不會自己開始：前面做完（或卡片指派給它）後，負責的 instance 會收到一則 `[Task board]` 通知，由它自己認領——通知與 `task get` 現在都會明講要先認領再開始，頁面也把這件事顯示出來。agent 如果沒認領就直接做指派給它的卡，也不會再隱形：只要它正在執行、手上沒有別張卡，這張卡的那一列、主任務的區塊、交接列、狀態旁和看板卡片都會顯示它在執行，並標上「尚未認領」（拖了一陣子還沒認領會加上警示）；系統不會替它改卡片的狀態。狀態取自 dashboard 本來就有的資訊，步驟取自對話的活動資料，權限和以前一樣；唯讀連結看得到狀態和子任務的變更，看不到通知的送達狀況。降版不會遺失資料：新資料表 `task_handoffs` 只增不改，舊版不會讀它。
