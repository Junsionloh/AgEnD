- **Settings → Accounts: sign Antigravity in from the dashboard, on this host and on a paired Windows computer (AGEND-113).** Antigravity's default sign-in now has **Sign in** / **Sign in again** like Claude Code's: the dashboard runs `agy acp --login` (agy 1.5.0 or newer), shows Google's link, and takes the code you paste back; it counts as signed in only when the command ended with exit 0 and `agy models` works. A paired computer has one Antigravity row of its own: Windows keeps a single Antigravity login per Windows user, so signing in there **replaces that computer's own Antigravity sign-in** (the page asks first, and `agend-runtime remote-setup accounts on` now says so). It is the one exception to "named accounts only" on a computer, and only for Antigravity; it stays behind the owner's local `accounts` switch, one sign-in at a time, the ten-minute limit and the audit record. On this host the row shows the signed-in account (the masked address from agy's own token file, read locally) and every one of Antigravity's quota pools (Gemini, Claude & others, Gemini 4 Argon) with every window it reports, a block per pool, as the usage panel's full card shows them; a finished dashboard sign-in reads the usage again at once, within the usage panel's own refresh limits. Google-account (subscription) sign-in only; no Google Cloud project, API key, named accounts or sign-out. An older agy keeps "Sign in on the host" with a note to update; the first-install page and `/login agy` in chat are unchanged. **Upgrade the server and its Runtimes together:** a Runtime now reports `signin-antigravity`, and a server will not offer the computer's Antigravity sign-in to one that does not.
