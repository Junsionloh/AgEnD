- **ACP agents catch up with terminal ones in six places (#3731).** An ACP instance can run under a named account (`backend_options.<cli>.credential_profile`: grok on its own `GROK_HOME`, agy on `--app_data_dir`; the child gets none of the default account's variables). `auto_pause_after` pauses an idle ACP instance (idle read from the turn, not the screen) and the next message wakes it. The context figure reaches the dashboard, `/ctx` and `/status` (agy's `usage_update`; grok's per-call token report over its model's window). With `skipPermissions: false`, a permission request is also a card in the Telegram or Discord topic (Allow once / Deny / Cancel the turn; fleet admins only). A message sent to a busy ACP agent is queued until the turn ends, as in a terminal (the default); `/steer <message>`, or `steer: true` from another instance, interrupts instead: both CLIs take it into the running turn without cancelling it (grok through its own `_x.ai/interject`, agy by folding a second prompt into the turn); only if one refuses, the turn is cancelled and the message runs next in the same session, ahead of the queue. Quota notices stay unsupported (ACP has no quota event). A stopped or signed-out ACP agent's Log no longer points at a View it does not have.
- **An ACP agent's work in the chat is anchored to its replies exactly.** The daemon sees both the agent's `session/update` stream and the fleet's answer to every reply, so each reply's block of steps now hangs above that reply's own bubble by its message id, not by guessing from its words, its time or "the last reply of the turn". A turn that ends with text and no `reply` call (agy's habit while a command runs in the background) leaves the same reply step as a call would have, so its steps no longer land on another bubble, and that text is not repeated as a step inside the block.
- **Interject with a key, and queued messages in their place.** While an agent works, Enter queues a message as before and Ctrl+Enter (⌘+Enter on a Mac) interjects it into the running turn; idle, both just send. A phone gets an Interject button beside Send, and the text under the box says what the keys do. `/steer text` goes the same way. The result is a mark on the message's own bubble ("Interjection · added to this turn", "turn stopped, sent next", "this agent does not take interjections, queued", "refused, sent as the next message") instead of a reply card. A message that waits for the running turn is shown at the bottom, below the work block, marked "Queued · sent when this turn ends"; once it is handed to the agent it sits after the previous turn's last reply, where it was actually sent, not where it was typed. `/ui/send` takes `steer: true`, and the instance status says `steer_supported`.
