- **Windows install command with a one-time token: any computer, no pairing code, no approval step.** Settings → Runtime → Connect a computer now makes a short-lived, single-use install command (a token valid for 15 minutes and one use; AgEnD stores only its SHA-256, a new command or *Revoke and close* ends it at once, and every issue, use and revoke is recorded). Pasted on any Windows computer, or handed to an AI agent running there, it installs the Runtime and connects it, with nothing to type and nothing to approve, in an interactive window or not (`powershell -NonInteractive`, CI). The command carries the AgEnD's server fingerprint: the Runtime first checks that the server it reaches is that AgEnD (an Ed25519 proof over a fresh nonce) and only then sends the token, which goes on the Runtime's standard input, never in a command-line argument, an environment variable or a file; the reply that carries the new credential is signed too. A computer already connected to this AgEnD just reconnects and the token is not used; one connected to another AgEnD gets its own profile. A computer that joins this way is announced on the Runtime page (**A new computer joined with an install command**, with **Revoke**). Expired, used, revoked, malformed and wrong-server tokens each stop with a clear message and a non-zero exit code. `agend-runtime connect` gains `--enroll-stdin` and `--server-fingerprint`; `install.ps1` is still the same fixed bytes pinned by the hash on the page. The pairing code stays interactive-only and moves under **Manual options**, the older route. Anyone who gets the command while it is valid and unused could connect their own computer as your Runtime, so treat it like a password; see `docs/remote-runtime.md` for the full security analysis.
